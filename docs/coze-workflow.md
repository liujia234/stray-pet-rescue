# Coze 领养智能匹配 Bot 工作流设计

## 📋 概述

| 项目 | 内容 |
|------|------|
| Bot 名称 | 流浪宠物领养智能助手 |
| 平台 | Coze（扣子） |
| 类型 | AI 对话 Bot |
| 目标 | 通过对话式交互，帮助领养人快速找到最适合的流浪宠物 |
| 配套项目 | [流浪猫狗寻回领养救助平台 - 微信小程序](../README.md) |

## 一、产品价值

### 为什么要做 Coze Bot？

| 痛点 | 解决方案 |
|------|----------|
| 领养表单填写门槛高，用户流失 | 对话式交互，像聊天一样描述需求 |
| 小程序受微信域名限制，手机端 AI 不可用 | Coze Bot 在微信内可直接运行（Coze 有微信渠道） |
| 只靠冷冰冰的列表 + 匹配算法 | Bot 可以用"懂宠物的朋友"语气推荐，更有温度 |

## 二、工作流架构设计

### 完整流程图

```
用户对话输入
    │
    ▼
┌─────────────────┐
│ 1. 意图识别节点   │ ← LLM 分析用户意图
│    (LLM Node)    │   判断：领养需求 / 宠物咨询 / 闲聊
└────────┬────────┘
         │
    ┌────┴────┐
    │ 领养需求? │──否──→ 知识库问答 → 返回答案
    └────┬────┘
         │ 是
         ▼
┌─────────────────┐
│ 2. 信息提取节点   │ ← LLM 结构化提取
│    (LLM Node)    │   输出 JSON：{城市, 住房, 偏好, 经验, 空间}
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 条件补全节点   │ ← 缺失必要字段时追问用户
│    (LLM +       │   "还没有告诉我你住在哪个城市呢~"
│     Conditional) │
└────────┬────────┘
         │ 条件完整
         ▼
┌─────────────────┐
│ 4. 匹配引擎节点   │ ← Code Node 执行权重匹配算法
│    (Code Node)  │   输入：用户条件 JSON
│                  │   输出：Top 5 匹配结果
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 5. 推荐生成节点   │ ← LLM 将结果转为人性化对话
│    (LLM Node)   │   输出：温馨推荐语 + 宠物卡片信息
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 6. 追问引导节点   │ ← 询问是否需要更多筛选或领养指导
│    (LLM Node)   │   "想了解哪只的具体信息？"
└─────────────────┘
```

## 三、节点详细设计

### 节点 1：意图识别

```yaml
节点类型: LLM
模型: DeepSeek-V3 / 豆包
输入: 用户最新消息 + 对话历史
系统提示词: |
  你是一个宠物领养助手。请判断用户意图：
  1. "领养需求" - 用户想领养宠物，描述了自己的条件
  2. "宠物咨询" - 用户询问领养流程、养宠知识等
  3. "闲聊" - 打招呼、感谢、其他

  输出仅一个 JSON：
  {"intent": "领养需求", "confidence": 0.95}
输出: JSON 对象 → 传递给下一节点
```

### 节点 2：信息提取

```yaml
节点类型: LLM
模型: DeepSeek-V3 / 豆包
输入: 用户原始消息
系统提示词: |
  从用户的消息中提取领养条件，输出 JSON：
  {
    "city": "城市名 或 ''",
    "housingType": "own/rent/''",
    "hasExperience": "yes/no/''",
    "space": "空间描述 或 ''",
    "lifestyle": "安静/活跃/陪伴/新手 或 ''",
    "preferType": "dog/cat/all",
    "preferBreed": "品种 或 ''",
    "completeness": 0-100   # 信息完整度评分
  }

  示例：
  用户："我在北京租房，想养一只安静的猫咪"
  输出：{"city":"北京","housingType":"rent","preferType":"cat","lifestyle":"安静","completeness":40}
输出: JSON → 传递给节点 3
```

### 节点 3：条件补全

```yaml
节点类型: Conditional + LLM
判断逻辑: |
  if completeness >= 70:
      → 进入节点 4（匹配引擎）
  else:
      → 生成追问语句，询问缺失的关键字段

追问策略:
  - completeness < 30: 开放式引导
    "很高兴你想领养宠物！先告诉我你在哪个城市呀？"
  - completeness 30-70: 针对性追问
    "了解了！再告诉我你是租房还是自己的房子呢？"
  - completeness >= 70: 确认后进入匹配
    "信息差不多了，我帮你匹配最合适的宠物~"
```

### 节点 4：匹配引擎

```yaml
节点类型: Code (JavaScript/Python)
代码逻辑: |
  // 与小程序 match-engine.js 算法保持一致
  function matchPets(userCondition, petDatabase) {
    const weights = {
      cityMatch: 0.15,
      typeMatch: 0.25,
      breedMatch: 0.20,
      spaceMatch: 0.20,
      experienceMatch: 0.10,
      characterMatch: 0.10
    }

    return petDatabase
      .filter(p => p.status === 'available')
      .map(pet => ({
        ...pet,
        score: calculateScore(userCondition, pet, weights)
      }))
      .sort((a, b) => b.score - a.score)
      .slice(0, 5)
  }
输入: 节点 2 的用户条件 JSON
输出: Top 5 匹配宠物列表 [{pet, score, matchDetails}]
```

### 节点 5：推荐生成

```yaml
节点类型: LLM
模型: DeepSeek-V3 / 豆包
系统提示词: |
  你是一个有温度的宠物领养顾问。根据匹配结果，用温暖自然的语气推荐宠物。
  要求：
  - 像朋友推荐一样，不要像机器列表
  - 每只宠物一句话亮点
  - 标注匹配度%
  - 引导用户进一步了解

  输出格式示例：
  根据你的条件，我帮你找到了 3 只特别适合的毛孩子 🐱

  🥇 No.1 花花 | 匹配度 92%
  安静温柔的三花猫小姐姐，已绝育，最适合公寓生活~
  
  🥈 No.2 团子 | 匹配度 85%
  ...
  
  想了解哪只的更多信息呢？我可以给你讲讲它们的故事~
```

### 节点 6：追问引导

```yaml
节点类型: LLM
触发: 用户回复感兴趣后
输出: 展示宠物详情 + 领养流程指南 + 救助站联系方式
```

## 四、知识库配置

### 宠物信息库

| 字段 | 说明 |
|------|------|
| name | 宠物名称 |

| breed | 品种 |

## 六、效果评估指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 意图识别准确率 | 正确识别"领养需求"的比例 | > 90% |
| 信息提取完整率 | 一次对话收集到 70%+ 信息 | > 70% |
| 匹配推荐点击率 | 用户点击查看详情 / 总推荐 | > 50% |
| 对话完成率 | 完成完整匹配流程 / 开始对话 | > 60% |

## 七、后续迭代方向

1. **多模态输入**：用户上传理想宠物照片 → AI 识别外观特征 → 匹配相似宠物
2. **跟进机制**：用户收藏宠物后 3 天未查看 → Bot 主动推送提醒
3. **领养后关怀**：定时推送养宠知识、提醒疫苗/驱虫时间
